01 / Software & hardware

Nocturne

The Colmi R02 is a twenty-dollar smart ring that ships with an app I didn’t want to run. Nocturne is what I use instead.

It reads the ring over Bluetooth, keeps every sample in a local SQLite file that never leaves the machine, and renders the parts I actually check in the morning: a sleep score I can interrogate, the night broken into stages, resting heart rate, and seven-day trends.

02 / Rust · networking

DNS resolver & security monitor

A resolver that answers the question and then watches itself being asked.

It parses DNS off the wire rather than leaning on a library, caches by TTL, signs every answer with an ECDSA key over RRSIG/DNSKEY, serves DNS-over-HTTPS, and drops ad and tracker domains before they ever leave the network.

The part I cared about is the threat engine. Every query gets scored on the Shannon entropy of its subdomain labels, label length, per-IP rate, and how many unique subdomains one parent domain is suddenly growing — the signature of DNS tunneling. Anything over the line lands on a watchlist with the evidence attached.

Captured from the resolver running locally — real traffic, real numbers

03 / C++ · SDL

Red-black tree visualizer

Type a number, press insert, and watch the tree go find the slot it belongs in.

Then watch it recolor and rotate to stay balanced. Delete runs the same machinery backwards. The tree itself was the easy half — the work went into the layout reflow, so a growing tree spreads out instead of piling nodes on top of each other mid-rotation.

04 / Platform · ran it live

Ready Player Zero

A capture-the-flag event I built the platform for, then ran: three keys, three gates, one champion.

Node and SQLite behind nginx, with team registration, flag validation, a live scoreboard, and an admin panel for moving the gates mid-event. The hands-on challenges lived in a separate Ubuntu container reachable only over SSH — no internet, one CPU, half a gig of RAM, so a competitor who broke out of a challenge broke out into nothing.

06 / Python · written at Fannie Mae

          
Two tools for the people who run the firewalls

          
Both of these started the same way: watching a question that should take one minute take an afternoon, because the answer was spread across every device on the network.

          
Internal tooling — the code and the consoles stay at Fannie Mae, so there is nothing here I can show you

        

        

          

            
Tool one

            
Ask every firewall at once

            
Panorama will happily talk to one firewall at a time. That falls apart when the question is where did this traffic go? and the honest answer is “it could be any of them.”

            
So this drives the Panorama API directly: one query fans out across every firewall in scope, kicks off packet captures where they’re needed, and collects the results in one place. Chasing traffic that never resolved stopped being a device-by-device hunt.

          

          

            
Tool two

            
Quarterly firewall hygiene

            
Rulesets rot. The same rule gets written twice by two people. A new rule quietly contradicts an old one. A change meant to tighten one path widens another, and nobody notices until someone goes looking.

            
This parses an exported CrowdStrike ruleset and reports what’s actually in it — duplicates, contradictions, and any rule that loosens or restricts access more than it was meant to. It ran as part of the quarterly firewall hygiene review.
